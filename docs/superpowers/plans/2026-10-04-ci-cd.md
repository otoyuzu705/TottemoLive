# Windows／Mac向けCI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Windows／Macの検証と配布ビルドを自動化し、両方を手動実行可能にする。

**Architecture:** 検証とビルドを再利用可能なGitHub Actionsワークフローにまとめ、CIと配布ワークフローから呼び出す。配布ワークフローは手動実行でartifactを保存し、タグ実行のみ全ビルド成功後にGitHub Releasesを公開する。

**Tech Stack:** GitHub Actions、Go、Wails v2、Node.js、Svelte、PowerShell、Python標準ライブラリ。

**Spec:** `docs/superpowers/specs/2026-10-04-ci-cd-design.md`

## Global Constraints

- Windows x64、Mac Intel、Mac Apple Siliconを対象にする。
- FFmpeg／ffprobeは同梱せず、利用者が別途インストールする。
- Demucsは現在と同じ任意機能とする。
- CIと配布用ビルドの両方をworkflow_dispatchで手動実行できるようにする。
- 手動実行によるGitHub Releasesへの公開は行わない。
- GitHubへのpush、タグ作成、実際の公開は今回のローカル実装に含めない。

## Review Focus

1. 手動実行が誤って公開しないこと：releaseジョブのイベント条件を確認する。
2. 一部OSのビルド失敗時に公開しないこと：releaseジョブのneedsと成功条件を確認する。
3. MacのZIP展開後に実行権限が残ること：dittoで梱包し、展開後の.app内実行ファイルを確認する。
4. Finder起動時にFFmpegが見つからないこと：絶対パスの環境変数を設定して実行する手順を検証する。
5. 不正なタグがバージョン設定へ流入しないこと：タグ検証スクリプトを正常値・不正値で実行する。

### Task 1: 再利用可能な検証・ビルド

**Files:** `.github/workflows/build.yml`、`.github/workflows/ci.yml`、`wails.json`

**Interfaces:** build.ymlはworkflow_callで呼び出し、各OSのartifactを生成する。ci.ymlはPR、main／devへのpush、workflow_dispatchを受ける。

- [x] Goの依存バージョンと利用可能なGitHub Actionsランナーを公式情報で確認する。
- [x] checkout、setup-go、setup-nodeの公式Actionsを使用する。Goはgo-version-file: go.mod、Nodeは24、npmキャッシュはfrontend/package-lock.jsonを指定する。
- [x] Windows／Mac両アーキテクチャをmatrixに設定し、FFmpeg／ffprobeをインストールして起動確認する。
- [x] フロントエンドを次のコマンドで検証する。

```sh
cd frontend
npm ci
npm run check
npm test
npm run build
```

- [x] GoとWailsを次のコマンドで検証する。Wails CLIはgo.modからバージョンを取得してインストールする。

```sh
go test ./... -count=1
go vet ./...
wails build -clean -m -nosyncgomod -platform darwin/arm64
```

- [x] wails.jsonのfrontend:installをnpm ciに変更する。
- [x] actionlintで両ワークフローを検証し、ローカルMacのビルドを確認する。

### Task 2: 配布パッケージとリリース

**Files:** `.github/workflows/release.yml`、`scripts/package.py`、`scripts/set-version.py`、`docs/INSTALL.md`

**Interfaces:** release.ymlはv*タグとworkflow_dispatchを受け、build.ymlを呼ぶ。package.pyはOS別ZIPを作り、SHA-256を出力する。set-version.pyはタグを検証しwails.jsonのinfo.productVersionを更新する。

- [x] タグを環境変数で渡し、正規表現でバージョン形式を検証してからJSONを更新する。シェルコードとしてタグを展開しない。
- [x] WindowsはPythonのzipfile、MacはdittoでGUI成果物とINSTALL.mdをZIP化する。出力先をdistに統一する。
- [x] 手動実行ではartifactだけを保存する。releaseジョブは次の条件とbuildジョブへのneedsを持たせる。

```yaml
if: github.event_name == 'push' && startsWith(github.ref, 'refs/tags/v')
permissions:
  contents: write
```

- [x] 全artifactを集めてSHA256SUMSを生成し、gh release createでZIPとチェックサムを公開する。
- [x] 不正タグで更新が拒否されることと、正常タグで製品バージョンが更新されることを一時ディレクトリで確認する。
- [x] Macパッケージを展開し、.app、利用手順、実行権限、チェックサムを確認する。
- [x] 手動イベントと失敗時のジョブ依存関係をactionlintとコードレビューで確認する。

**Files:** `README.md`、`docs/INSTALL.md`、`CLAUDE.md`

**Interfaces:** READMEは開発者向けCI/CD操作、INSTALLは配布物の利用者向け導入を説明する。

- [x] WindowsのWebView2とFFmpeg、MacのFFmpeg、任意のDemucs、未署名アプリの初回起動手順を記載する。
- [x] MacではTOTTEMOLIVE_FFMPEGとTOTTEMOLIVE_FFPROBEに絶対パスを設定し、.app内の実行ファイルをターミナルから起動する手順を載せる。
- [x] workflow_dispatchは既定ブランチにワークフローが存在する必要があることと、Actions画面での実行・ダウンロード操作を説明する。
- [x] タグの形式、公開トリガー、各配布物のアーキテクチャ、署名・公証の範囲を説明する。
- [x] 最終変更に対してactionlint、Goテスト・vet、フロントのcheck・test、Macビルドを実行する。
- [x] git diff --checkで差分を確認し、日本語メッセージでコミットする。
- [x] 実際に実行した検証とWindows／GitHub上で未実行の検証を区別して報告する。
