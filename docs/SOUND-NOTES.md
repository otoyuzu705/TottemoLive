# 音質の検証記録

音質の追い込みで測ったこと・分かったことの記録。設計(何をどう作るか)は `TottemoLive-design.md` が正で、ここは測定の結果と、次に何を試すかのメモ。

## 2026-11-05 全体のバランスの崩れ(低音の明瞭さの修正の後)

### 状況

`feature/bass-clarity`(残響のゲインを √本数 に直し、低音の濁りを減らした)で、低音の明瞭さは改善したが、「全体のバランスがおかしい・どこかが足りない」と感じた。

### 測り方

ユーザーのプロジェクト(アリーナ、リスナー x=0・y=25 m、メイン2本 ±12 m、サブ +3 dB・60 Hz、`reverb.mix` 0.24)に「青天のフイルム」を入れて CLI で書き出し、原音と 1/3オクターブごとに比べた(全体のエネルギーをそろえた差)。キャッシュは切る(`TOTTEMOLIVE_CACHE=off`)。

```
go run ./cmd/tottemolive-cli render project.json -o out.wav --set spatial.hrirSet=brown-duda
python3 scripts/band_balance.py 原音.wav out.wav 別の書き出し.wav ...
```

処理を1つずつ外した書き出し(`--set reverb.mix=0`、`spatial.airAbsorption=0`、`spatial.headShadow=0`、PAの色付け・サブを切る、メインを1本にする)を並べて、どの処理が効いているかを切り分けた。

### 結果(原音との差、dB)

| 帯域 | 今の設定 | 原因 |
|---|---|---|
| 40〜63 Hz | +2〜+3 | サブのレベル(`sub.levelDb` +3)。設定どおり |
| 300 Hz〜1 kHz | −1〜−2 | (下の谷の裾) |
| 1.25〜2.5 kHz | −3.5〜−4.6 | 左右2本のメインの打ち消し合い |
| 5〜8 kHz | −4〜−7 | 合成HRIRの頭の影 + 空気吸収 |
| 10〜16 kHz | −9〜−20 | 同上 |

聴感では「ボーカル(1〜3 kHz)が引っ込み、高域がこもり、相対的に低音が前に出る」方向。

### 原因

1. **1〜3 kHz の谷(左右2本のメインの打ち消し合い)**: 中央の音(ボーカルなど)が左右のメインから両耳に届き、わずかな時間差(耳の間の時間差 約0.22 ms)で重なって、約2.2 kHz を中心に打ち消し合う(ステレオの「ファントムセンターの谷」)。
   - メインを1本にすると、谷は消える(±1 dB 以内)
   - 頭の影・空気吸収・PAの色付け・サブを全部外しても残る
   - 実際の会場では初期反射が谷を埋めるが、今の合成の会場IRは、プリディレイの後すぐ密な拡散音で始まり、初期反射を持たない。残響を減らすほど谷が露出する(√本数の修正で残響が約3 dB 減り、谷が 0.5 dB ほど深くなった)
2. **高域落ち(合成HRIR + 空気吸収)**:
   - 合成HRIR(`synthetic`、既定)の頭の影が、16 kHz で約 −15 dB、10 kHz で約 −6 dB。Brown–Duda(`brown-duda`)なら −2〜−3 dB
   - 空気吸収(約27 m)が、16 kHz で約 −9 dB、8 kHz で約 −3 dB。`spatial.airCompensation` は 0(補正なし)だった
3. **低音の +2〜+3 dB**: サブのレベル +3 dB による。ユーザーの設定どおり

`feature/bass-clarity` の変更自体の影響は、どの帯域も 1 dB 前後(1.6〜2 kHz と 10〜16 kHz が少し下がる)。もとからあった偏りが、低音がすっきりしたことで目立つようになったと考えられる。

### 設定だけで原音のバランスに近づけた組み合わせ

| 設定 | 値 | 効果 |
|---|---|---|
| `spatial.hrirSet`(HRIRの種類) | `brown-duda` | 10 kHz 以上のこもりが取れる(16 kHz: −20 → −12 dB) |
| `spatial.airCompensation`(空気吸収の補正) | 1 | 高域が戻る(16 kHz: −12 → −0.2 dB) |
| `pa.presenceHz` / `pa.presenceDb` / `pa.presenceQ` | 2000 Hz / +4 dB / 1 | 1〜3 kHz の谷を埋める(2 kHz: −4.1 → −0.6 dB) |

3つ合わせると、25 Hz と 40〜63 Hz(サブの設定)を除いて、原音とほぼ ±1.5 dB に収まった。**まだ聴いて確かめていない**(数字が近くても、聴いた印象が良いとは限らない)。

### 次にやること

- [ ] 上の3つの設定を聴いて、印象を確かめる
- [ ] 印象が良ければ、1〜3 kHz の谷は、プレゼンスで後から埋めるのではなく、会場IRに初期反射を加えて自然に埋める方向を検討する(実際の会場の仕組みに近い)
- [ ] 既定値(`spatial.hrirSet`、`spatial.airCompensation`)を変えるかは、聴いた結果で決める。まだ変えていない
- 低音の余韻(到達から 250 ms 以降の低域残響)は消したくない。低音の明瞭さに手を入れるときは、余韻を何 dB 削るかも測って示す

## 関連: Linux版でプレビューのシーク時に固まる問題(2026-11-05)

Ubuntu 22.04(WebKitGTK 2.50 + GStreamer 1.20)で、プレビューの再生位置を変えると画面が固まる問題を直した(PR #47、`fix/linux-audio-seek-freeze` → `dev`、未マージ)。

- 原因: `<audio>` が曲をまるごと先読みする経路(`preload="auto"`)でシークすると、WebKitの画面スレッドとGStreamerが互いを待ってデッドロックする。WebKitは一度再生した `<audio>` の次の読み込みを先読みに戻すので、`preload="metadata"` だけでは、音源を差し替えた後のシークで再び固まる
- 修正: `preload="metadata"` にし、音源の差し替えのたびに `<audio>` を作り直す
- 残り: Linuxのアプリでの最終確認、Windows・Macで再生・シーク・A/B・音量・スペクトラムが今まで通りかの確認。確認できたらマージし、`dev` を `feature/bass-clarity` に取り込む(取り込むまで、このブランチを Linux で動かすとシークで固まる)

Linuxで `wails dev` を動かすときは `-tags webkit2_41` が要る(`docs/DEVELOPMENT.md`)。Homebrewの `ld` が PATH の先にある環境では、`CGO_LDFLAGS="-B/usr/bin"` も付けてシステムの `ld` でリンクする。
